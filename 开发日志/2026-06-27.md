### 🎬 飞入动画修复 ×2

**问题 1：贴纸提前出现** — 飞行动画播放期间，日历格上已经显示了刚保存的贴纸，动画结束后贴纸"闪现"。

- **根因**：`Step6Preview` 在 mount 时立即 `saveRecord()`，记录写入 localStorage。`CalendarPage` 通过 `getTeasForDay()` 实时读取，立刻渲染贴纸。飞行覆盖层只是视觉叠加，底层贴纸早已可见。
- **修复**：`CalendarPage.tsx` — `teasByDay` useMemo 增加 `flyInRecord` 依赖，动画播放期间过滤掉 `flyInRecord.id` 对应的记录。动画结束后 `flyInRecord` 清空，贴纸自然出现。

**问题 2：飞入位置不精准** — 贴纸没有精准贴到对应日期方格。

- **根因**：`requestAnimationFrame` 在 React commit 后但在浏览器 paint 前触发，DOM 布局可能尚未稳定。fallback 计算使用硬编码 `gridTop = 140`，不同屏幕尺寸偏差大。
- **修复**：
  - 改用双 RAF（`requestAnimationFrame` 嵌套），确保浏览器完成 layout + paint 后再测量
  - 新增 `gridWrapperRef` 绑定到日历网格 DOM，fallback 时从 ref 获取真实网格位置
  - fallback 计算改用网格容器的 `getBoundingClientRect()` 动态推算

|------|------|
| `CalendarPage.tsx` | teasByDay 过滤 flyInRecord、双 RAF 定位、gridWrapperRef |

### 💾 记录保存失败修复

**问题**：记录以前月份的奶茶时无法保存，且无任何错误提示。

**根因分析**：
1. **localStorage 配额静默失败**：base64 图片体积大（100-500KB/张），多张记录后 localStorage（5-10MB 上限）满，`saveAll()` 返回 `false`，但 `Step6Preview` 只 `console.warn`，用户完全不知道保存失败
2. **保存失败后仍可撕下**：即使 `saveRecord()` 失败，`savedRecord` 状态仍然被设置，用户可以撕下小票、看到飞入动画、贴纸出现在日历上——但实际未持久化，刷新后消失
3. **DEFAULT_DATE 静态值**：`draftStore` 中默认日期在模块加载时计算一次，跨天使用会导致日期偏移

**修复**：
- `Step6Preview.tsx`：保存失败时显示错误 UI（⚠️ + 提示文字 + 重试/去清理按钮），不设置 `savedRecord`，阻止撕下操作
- `Step6Preview.tsx`：导入 `toast.error()`，保存失败时弹出红色错误 toast（5 秒）
- `draftStore.ts`：`DEFAULT_DATE` 改为 `getToday()` 函数，每次创建空草稿时动态获取当天日期

### 🔄 修改文件

| 文件 | 改动 |
|------|------|
| `Step6Preview.tsx` | 新增 saveFailed 状态、错误 UI、错误 toast、阻止失败后撕下 |
| `draftStore.ts` | DEFAULT_DATE 静态常量 → getToday() 动态函数 |
